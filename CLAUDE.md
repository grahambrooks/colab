Exit codes from `colab refactor` (also documented in `--help`):

| Code | Meaning |
| ---- | ------- |
| 0    | Success — no changes needed, or `--write` succeeded. |
| 1    | Generic / configuration error. |
| 2    | Script parse error. |
| 3    | Unsupported namespace or operation. |
| 4    | I/O error. |
| 10   | `--check` found changes that would be made. |
| 11   | `--write` found conflicts and wrote nothing (`--allow-conflicts` overrides). |
| 12 | `colab test` found a pack case that fails. |

Defaults: `--format human` on a TTY implies `--write`; everything else (`json` / `ndjson` / `diff` / `sarif` / `github`, or non-TTY stdout) defaults to `--dry-run`. `--check` overrides both.

`text` (`colab-lang-text`) has no grammar: `text::literal` (every
occurrence) and `text::word` (not inside a longer word) take `replace` /
`delete` on any text file, skipping common binary formats. It is the one
backend whose `is_file_relevant` takes every path; the contract test
`no_backend_claims_a_path_it_cannot_parse` exempts it by name.

`.h` is claimed by both `c` and `cpp` — the extension cannot distinguish
them. Both run over `.h` files in a mixed script; every op is idempotent
so the result is the same, at the cost of one extra parse.

`crates/colab-dsl/build.rs` runs `lalrpop::process_root()` (editing `src/codemod.lalrpop` requires a rebuild — generated `codemod.rs` lives in `OUT_DIR`). `crates/colab-cli/build.rs` shells out to `git rev-parse --short HEAD` to embed a version suffix, so builds must happen inside a git checkout.

## Dogfooding — develop colab with colab

Follow [`docs/dogfooding.md`](docs/dogfooding.md). In short:

- Pin a binary with `scripts/dogfood.sh` and run `.dogfood/colab`, never
  `cargo run`, so a broken working tree cannot break the tool.
- For a mechanical change across several sites, use colab:
  `rust::pattern` via `refactor` / `find`, or `rename` / `mv` /
  `references` / `safe-delete` / `action` through rust-analyzer. Use
  `Edit` only for one-off edits.
- Before writing, preview with `find` or `--format diff`. Apply with
  `--write --bisect 'cargo check -q --workspace --tests'`. `--verify`
  checks after *each* rule, so it rejects a change whose rules only
  compile together.
- Log every case where colab could not express the change, or needed its
  output hand-fixed, in [`docs/dogfood-log.md`](docs/dogfood-log.md). Fix a
  small one in the same commit. Name the colab command in the commit body.

## Architecture

A codemod runs through a four-stage pipeline; see [`docs/architecture.md`](docs/architecture.md) for the diagram and module map.

```
script text  →  colab_dsl::parse        →  colab_dsl::ast (raw AST, possibly many Match blocks)
             →  colab_dsl::compile      →  colab_dsl::Refactoring (Vec<Box<dyn Operation>>)
                  uses BackendRegistry from colab_core
             →  colab_core::walker      →  Operation::apply (e.g. colab_lang_go::imports::ImportRename)
```

Key invariants when changing this code:

- **`CodeTransformer` is the only contract `walker.rs` knows about.** It takes `&str` (not `&String`) and returns the rewritten source. Returning the input unchanged is the signal to skip the write — preserve that. The walker calls `apply_at(path, source)`, which additionally reports which rules fired; `apply(source)` remains the path-blind fallback.
- **`LanguageBackend` is the extension point.** Adding a transform = new `Operation` impl in the appropriate `colab-lang-*` crate + matching arm in that crate's `LanguageBackend::build_rule` + a `registry.register(Box::new(<Backend>))` line in `colab-backends/src/lib.rs::registry` (the *only* registration site — `colab-cli`, the corpus harness, and the MCP tests all call it). Do **not** add backend dependencies to `colab-dsl` or plumb language details into `walker.rs` / `cli.rs` beyond that one registry line.
- **`colab-dsl` must not depend on any `colab-lang-*` crate at runtime.** Use it as a `dev-dependency` for tests only. The CI matrix relies on this so a broken backend cannot block unrelated work.
- **Rules are gated per file, not merely expected to no-op.** `Refactoring::apply_at` skips any rule whose `is_file_relevant` rejects the path, so a Go rule never parses a `.rs` file. `Operation::apply` must still be a no-op for irrelevant input (the path-blind `apply` composes rules unconditionally), but the engine no longer relies on it for cross-language safety.
- **`Operation::prefilter` must be a *necessary* condition, or `None`.** It returns a literal that has to appear in the source for the rule to change anything; when it is absent, the tree-sitter parse is skipped entirely. Returning a literal only promises that its absence implies a no-op — an over-broad literal costs performance, never correctness. **`ensure`-style operations must return `None`**, since they act precisely when the target is absent. A too-narrow prefilter shows up as a corpus idempotency failure.
- **`<lang>::pattern` is one engine, fourteen thin adapters.** Matching, rewriting, deletion, prefilter extraction, and tree printing live in `colab_rewrite::pattern`; a backend's `patterns.rs` supplies only its `PatternLanguage` — grammar, an expando char (`µ` where `$` cannot start an identifier), and context wrappers containing `@@PATTERN@@` — and, for Go, Python and JS, its `Qualifiers`; the `PatternOp` and `syntax_tree` are `colab_rewrite::language`'s. Fix matching bugs there, never in a backend. The prefilter is the longest *named-leaf* literal of the compiled pattern (leaves are compared by exact text, so it is sound); a pattern that parses in no context is `Error::UnsupportedOperation` naming every attempt. A match must account for every named child of the node it matches unless a `$$$` absorbs them (`Shape`): ast-grep's default strictness ignores trailing children, which let a rewrite drop an `else`, a third `Union` member or an anonymous class body. An item's modifiers are the one exception, and it is opt-in per backend (`PatternLanguage::modifiers`): a pattern that spells none is compiled again with the language's sentinel (`@ColabMods`, `pub(in colab_mods)`) in front. `TsLang::extract_meta_var` reads the sentinel as the reserved `$COLAB_MODS`, so that one form matches every combination and a rewrite gives them back; a spelled modifiers node must match token for token (`Shape::Tokens`). Where no sentinel can stand for them (JavaScript's anonymous `static`, TypeScript's keyword-only `private`), `PatternLanguage::modifier_tokens` lists them instead: an item pattern that does not spell its first child also compiles with `k` placeholders in front (`led_forms`, `k` ≤ 4), each kept only when the item has exactly `k` leading modifiers (the pattern itself then requires none), and `keep_modifier_tokens` puts back the ones a template leaves out. ast-grep skips anonymous tokens before a literal but not before a metavariable, so without these `$M() {}` misses `static m() {}`, and a rewrite of a matched `static async f()` dropped both keywords. Contexts in a backend's `also` list are compiled too and matched alongside, for text that parses as different nodes in different places (Python annotations: `generic_type`, not `subscript`).
- **`colab.toml` drives `colab fix`** (`colab-cli/src/config.rs`): `[run]`, `[formatters]`, `[patterns]`, `[[packs]]`; unknown keys are errors. `[patterns] macros` (a project's own Rust expression macros) is per-run state, `Run::set_macros`: the CLI sets it from the nearest `colab.toml` when it compiles a script (a `colab.toml` that does not parse is a warning there, never a failure), `fix` from its config, and MCP per tool call through `ToolProvider::macros(cwd)`; the engine reads `Run::current()` beside the language's own list. Built-in packs are `include_str!`ed from `examples/packs/` in `colab-cli/src/packs.rs::BUILTIN` — adding a pack there needs a corpus case and a README. `fix` compiles every pack, merges them with `Refactoring::combine` (each rule keeps its pack's name via `RuleNote::script`), and runs them through `run_compiled` with the config's settings as `refactor` flags.
- **`where` constraints narrow, never widen.** `colab_core::Constraint` is plain data. `colab_rewrite::pattern` (`Check`) evaluates it as a filter on the match list, before `find`, `rewrite` and `delete`, so the prefilter stays sound and `find` agrees with `refactor`. Every metavariable, node kind, regex and nested pattern is validated at compile time. `pattern` takes every constraint (`any` / `all` groups, sibling and position tests via `Test::Related` / `Nth` / `Field` / `Top`, which judge a match as the widest node spanning its text (`Top`: a direct child of the root, never inside a macro's contents), and a template may use only the pattern's own metavariables and `let`s); `symbol` and `call` take only `inside` / `not inside`, a syntactic code scope (`colab_rewrite::scope::Scoped`: the rule runs, then only the changed tokens inside — or outside — the scope patterns' matches are kept); every other module keeps the default `build_rule_where`, which rejects them by name (contract-tested). A `let $N = $F | step …` clause (pattern `replace` only, checked in `compiler::lower::lower_lets`) travels with the constraints as `Test::Let` so no backend signature changes; it narrows nothing, and `colab_rewrite::derive` applies its steps in `Rewriter::render`, after the bindings' nested matches are rewritten. A `pattern <name> = '…'` item names a constraint pattern; a reference is held as `colab_core::constraint::named_pattern` text until `compiler::names::resolve_names` replaces it (after includes are expanded), so backends only ever see code. A `rewriter <name> = '…' -> '…'` item is resolved there too, into a `let`'s first `rewrite(…)` step (`Transform::Rewrite`); the engine rewrites each of its matches inside the binding's span (`rewrite_with`, every compiled form), and nested `where` patterns likewise match in every form (`Forms`).
- **Import clauses are follow-ups, not rules.** `requires import` lowers to the backend's `import_module()` `ensure`; `drops import … when unused` lowers to `drop_unused_import`, a Go-only operation that errs towards "used". Both are wrapped with the rule in one `colab_core::WithFollowups` operation, which runs them only when the rule changed the file, drops before requires. Attribution stays with the rule, and idempotency holds.
- **DSL surface today: `match <lang>::<module> "<target>" [in "<glob>"] [in fences | and fences] [and prose] [where <constraint>, …] { [let $NEW = $FROM | <step> …] <action> [requires import "<x>"] [drops import "<x>" when unused] [message "<text>"] [severity error|warning|info] [id "<name>"] [url "<link>"] }`, with actions `replace "..."`, `delete`, `ensure`, `replace_call "<tmpl>"`, `create "<path>" '<template>'` (patterns only), and — for the config-file backends — `set '<value>'` / `insert '<value>'`.** Strings are double- or single-quoted, or raw (`r#"…"#`, `r##"…"##`, which may hold both quotes). `"…"` takes JSON's escapes (`\"`, `\\`, `\n`, `\t`; any other backslash is kept, `colab_dsl::ast::unescape`); `'…'` and raw strings are literal, so code patterns and templates keep their own backslashes. Code that writes DSL text quotes it with `ast::quote_double` (or a literal quote the text lacks), never by hand. `delete`/`ensure` use the `match_string` as the target. `replace_call` rewrites a matched call expression with a template using placeholders `$1`/`$2`/… (1-indexed positional args), `$args` (full arg list), `$func` (matched function name), `$$` (literal `$`). Templates that *do not rename the function* (e.g. `match go::call "f" { replace_call "f(ctx, $args)" }` — wrap-style) are intentionally non-idempotent and must be applied once; the corpus harness's idempotency check will fail any rule that loops, so verify with `--format diff` and apply with a single `--write`. colab warns about such rules at compile time (`Operation::advice`, `RuleNote::advice` → report warnings, `RuleCheck::advice` → `colab_dsl::check`'s per-rule warnings): a `replace_call` template that still calls the function, and a `pattern` template that is a match of its own pattern.
- **A created file is a `FileChange`, not a second channel.** `create` rules return files from `Operation::creates` (read on the text as the rule finds it; the rule's `apply` leaves that text alone); `Refactoring::apply_at` collects them in `ApplyOutcome::created`, and every emit site turns an outcome into changes with `FileChange::all_from_outcome`, whose created ones have `created: true` and `before` as on disk (a different file there is a rule conflict, the same text an unchanged no-op). `pipeline::prepare` clears them separately (`prepare_creations`: one path made twice with different text, or a file that appeared since the walk, is a conflict), `write` makes their directories and calls `Hooks::before_create` (the CLI's `--backup` lists them for `colab undo`), and `RunReport::record` counts them as changed, never scanned. A new emit site must use `all_from_outcome`, or the files are silently lost.
- **Conflicts are checked before anything is written.** `Operation::conflicts(before, after)` (default: none) is called for each rule that changed a file, with `before` as the rule found it and `after` as the whole script leaves it, so a later rule that adds a missing import clears the conflict. Checks must be syntactic and err towards silence: `symbol` renames onto an existing identifier (`colab_rewrite::rename_conflict`, all 14 source backends), and pattern templates that introduce an unimported qualifier (`colab_rewrite::pattern::Qualifiers`, Go, Python and JS: the languages whose imports bind the qualifier; the others stay silent rather than guess), and `pattern` / `call` changes that make a function call itself more often (`SourceLanguage::new_self_calls`, by name over `declarations` and `callees`, all 14 source backends). `--verify-lsp` adds the server's new error diagnostics as conflicts, credited to the rule whose own change holds the error's line (or the only rule that changed the file; `rule: None` when neither tells). Every write path (`refactor` normal, `--bisect`, `--verify`, MCP `colab.apply`) buffers its changes and writes nothing while any conflict stands, unless `--allow-conflicts` / `allow_conflicts`; exit 11. Each one also calls `colab_dsl::pipeline::prepare` (`colab_core::merge::prepare_writes`) just before writing: a file changed on disk since the run read it is three-way merged (base = as read, ours = as the run leaves it, theirs = disk) when the edits do not overlap, and is a conflict when they do (adjacent lines count, as in git); a conflicting file is never written, not even under `--allow-conflicts`, and backups keep the on-disk text. Rules themselves never merge: each sees the previous one's output. A rule that matched but left matches alone explains itself through `Operation::why_unchanged` (`RuleStat::unchanged`): a dead rule always, a rule that changed other files too (probed on the sampled files holding its prefilter literal, "already as the rule asks" dropped). `why_unchanged` must return `None` for a file the rule would change.
- **Semantic constraints are asked, never computed.** `where $X type "…"` / `$F resolves "…"` / `$T implements "…"` / `$F calls "…"` / `$F called_by "…"` are `Test::Semantic` (the last three walk the server's type and call hierarchies); the pattern engine filters on its other checks first (semantic ones are sorted last), then asks about every surviving match in one batch per check (`semantic::prefetch` → `Oracle::ask_all`, which `LspOracle` pipelines with `Session::request_all`), and `semantic::ask` reads the run's answer cache (keyed by file, text hash, span and question) before asking, and the binary installs `colab_lsp_client::semantic::LspOracle` (`OracleGuard`) only when `Refactoring::needs_oracle`. The current file comes from `semantic::at_path`, set by `apply_at`, `find::locate_all` and the near-miss probe. Any unanswerable question is recorded and `semantic_failure()` fails the run at the end of the walk, before writes; `colab-mcp` refuses such rules. The oracle, a phased run's scan facts and those failures belong to a `colab_core::run::Run`, never a static: the CLI enters one per command, `colab mcp` one per tool call, and the walker enters the caller's run on each rayon worker. A new run path must enter a run; a new thread or pool that applies rules must enter the caller's (`Run::current`).
- **Semantic edits are delegated, never computed.** `colab rename` / `colab mv` ask the language's own server and report its answer; colab still resolves no names itself. A server still indexing at the timeout is an error, not a partial rename.
- **File operations go through git or not at all.** A server's create / rename / delete becomes a `colab_core::fileops::FileOp` in a `ChangeSet` (replayed in order over a virtual copy of the files by `colab_lsp_client::edit::to_change_set`, so an edit's `before` is always the original content and `ChangeSet::origin_of` maps a final path back). `colab-cli/src/apply.rs` makes them with `git mv` / `add` / `rm` only inside a git work tree, refuses dirty paths unless `--allow-dirty`, writes edits after the operations (unstaged), and logs operations to `--backup` so `colab undo` / `--verify` reverse them. Outside git, the client advertises no `resourceOperations` and any it receives are refused. Never fall back to a plain filesystem move: it loses history and undo.
- **Symbol rename is single-file and syntactic.** `<lang>::symbol "X" { replace "Y" }` rewrites every identifier-kind tree-sitter node whose text equals `X` *within each file processed*. Narrow it by path with `in "<glob>"` (`colab_core::ScopedOperation`) when two crates share a name, or by code with `where inside '<pattern>'` (one function, one `impl`). Both are syntactic: there is no scope analysis (a shadowed local with the same name is also renamed) and no cross-file linkage (a struct moved to a new module would still need the user to update imports — the `<lang>::import` and `rust::crate` operations cover that). Rules act on one file each. M35 relaxed the *reading* half only: a `scan … as <name>` phase collects facts (`colab_core::facts`) from every file for later per-file rules to narrow on (`where $X in <name>`), `then { … }` orders stages, and `Refactoring::run_phased` runs them; every edit is still made by a per-file rule, and nothing resolves names across files. Every run path runs such a script: `Pipeline::execute` over a walk (`refactor`, `fix`, MCP `colab.preview` / `colab.apply`, `--bisect`'s first pass) or over one text (`--stdin`, MCP `colab.test_rule`, whose scans read that text); `find` / MCP `colab.find` through `Source::visit_phased`; `--changed-since` / `--staged` with `Pipeline::scan_over` (scans read the whole walk, rules change only git's files); and the one-rule-at-a-time runs (`--verify`, `--commit-per-rule`, `--split-pr`, the bisect search) after `pipeline::prepare_scans` installs the whole script's facts once ([`docs/architecture.md`](docs/architecture.md#phased-runs-scan-and-then)).
- **A run goes through `colab_dsl::pipeline`, never a copy of it.** `Pipeline::execute` is the one implementation of walk (`Source`: a tree walk, git's paths, or one text; phased when the script has scans) → `semantic_failure` → `Check::rewrite` (`--tidy`) → record → `Check::verify` (Markdown links, `--verify-lsp`) → `prepare` → `refuse` or `write` → near-miss probe → elapsed. Surfaces plug in through `Hooks` (stream unchanged files, `--baseline`, `--backup`, progress) and `Check`; checks needing crates `colab-dsl` / `colab-mcp` must not depend on are built by the binary (`colab-cli/src/cli/writes.rs`, MCP via `ToolProvider::checks`). Runs that apply rules one at a time (`--verify`, `--commit-per-rule`, `--split-pr`, the bisect search) compose the stage functions: `RuleRun` (one rule over a `Source`, its changes credited to the rule's script index), `prepare`, `refuse`, `write`. Build the `Source` once per run, not per rule. A new run path adds a `Source`, `Hooks` or `Check`; it does not re-sequence the stages.
- **Transforms must be idempotent** on their own output. The corpus harness (`crates/colab-dsl/tests/corpus.rs`) re-applies every script and asserts the second pass is a no-op. When matching syntactic constructs, prefer exact-equality on the relevant tree-sitter node (e.g. an import path) over substring matching — substring matches break composition (see `colab-lang-go/src/imports.rs`).
- **Unknown namespaces must fail loudly, and name the alternatives.** `BackendRegistry::get` returning `None` is mapped to `Error::UnsupportedOperation` in `compiler::lower::lower_match`; never silently fall back to a default transform. Backends reject unknown modules and unsupported actions through `LanguageBackend::unsupported`, which lists the valid names and adds a "did you mean" via `colab_core::suggest` — use it rather than hand-rolling a message, and never format a `RuleSpec` with `{:?}`.
- **A rule that matches nothing is a reportable event, not a silent success.** `RunReport` carries per-rule match counts (`RuleStat`); every output surface warns on `files_matched == 0`. Anything that adds a new way to run rules must keep that attribution intact. Dead rules are also *explained*: an op that targets a value (import path, call name, identifier) implements `Operation::near_miss_target` + `observed_targets`, returning values in the **same normalized form its matcher compares**, and every run path calls `colab_core::near_miss::probe` after the walk so `rules[].near` appears on CLI and MCP alike. `ensure`-style ops keep the defaults.
- **Output is for a machine first.** `colab-core::render` is the single serializer both `colab-cli/src/format.rs` and `colab-mcp` use — compact JSON, unchanged files omitted, diffs capped, and the `visited`/`scanned`/`changed` counters kept distinct so an empty result is self-explaining. Do not add a second, surface-specific shape. `RunReport`'s fields are `pub(crate)`: other crates read it through accessors of the same names (`report.rules()`, `report.files_changed()`) and add to it only through its methods (`warn` / `warn_all`, `add_conflict(s)`, `add_rule`, `rules_mut`, `add_branch`, `set_file_ops`, `skip_all`, and `set_counts` / `set_bytes` / `set_elapsed` for the reports no walk builds). The counters otherwise come from `record` / `record_walk` alone. Add a method rather than widen a field.
- **Parse through `colab_rewrite::parse_cache::parse`.** Every source backend's `parse` and the pattern engine do, so consecutive rules over an unchanged text share one tree (M10.6; rules still see each other's output, so semantics are untouched). A new parser of a source text should use it too.
- **`llms-full.txt` is generated.** It is `colab_mcp::resources::llms_full()` (README, `docs/dsl.md`, `docs/cli.md`, `docs/features.md`, `docs/operations.md`), and a test fails when it is stale: after editing those, run `COLAB_BLESS=1 cargo test -p colab-mcp`.
- **Never hand-roll a tree walk or an edit application.** `colab-rewrite` owns `apply_edits` (reverse byte order, so earlier offsets stay valid), `delete_lines`, `visit_all`, and `rename_nodes_by_text`. These were duplicated across 12 backends until they were extracted; re-introducing a private copy re-introduces the bug-fixed-in-one-of-twelve problem. The same went for the operations themselves: `<lang>::symbol`, `<lang>::call` and `<lang>::pattern` were twelve near-identical copies each, and are now `colab_rewrite::language::{SymbolRename, CallReplace, PatternOp}`, configured by the backend's `static LANG: SourceLanguage` (a `RENAME_KINDS` list, a `CallShape`, a `PatternLanguage`). A backend never implements them again; the contract test `every_source_backend_has_the_common_floor` checks each one has them.
- **Cross-backend contracts are tested generically** in `colab-backends/tests/contracts.rs`: `ensure` ops must have no prefilter, a prefilter must be derived from the target and its absence must imply a no-op, and every module name must be spellable as a DSL namespace segment (the `c::include` collision). A new backend inherits all of these without anyone remembering to wire them up.
- **Every new backend must add at least one corpus case** under `tests/corpus/<lang>/<case>/{script,input/,expected/}` before it merges. Each case also carries generated `rules.expected` (per-rule attribution + near misses) and `find.expected` (`colab find` locations + bindings); write them with `COLAB_BLESS=1 cargo test -p colab-dsl --test corpus` and review the diff — see `tests/corpus/README.md`.
- **A new feature adds a conformance file; a new backend adds a column.** `tests/conformance/<feature>.toml` holds one case per source language (`na` with a reason, or `xfail` with a one-line diagnosis), and `docs/conformance.md` is generated from them (`COLAB_BLESS=1 cargo test -p colab-dsl --test conformance`). A fix that makes an `xfail` pass fails the test until the `xfail` is removed.
- **Markdown is addressed by structure** (`colab-lang-markdown`, on `tree-sitter-md`). `outline::headings` is the one source of sections: a section runs to the next heading of the same or higher level (computed, not the grammar's `section` node, which skips setext headings), and an address is a heading path matched on the text a reader sees, or a `#slug` (GitHub rules). `row` and `item` look only in a section's own text (before its first subsection); `link` matches destinations by trailing path segments. An ambiguous address changes nothing and says why (`why_unchanged`); `set` / `insert` / `ensure` create what is missing, so they have no prefilter. Links are checked per run, not per rule: `colab-cli/src/markdown.rs::check_links` compares every Markdown file under the run's paths as it is and as the run would leave it, and each newly broken link is a file-level conflict (`--no-link-check` skips it). `colab outline` / `section` / `links` and MCP `colab.outline` / `colab.section` / `colab.edit_markdown` read and write by the same rules.
- **Config-file backends compare values by meaning.** `set` must be a no-op when an equal value is present however it is formatted, and `set` / `insert` must return `None` from `prefilter` (they act when the target is absent; the contract test enforces it). A file that does not parse is returned unchanged.
- **Scope globs ignore a leading `./`** (`ScopedOperation`), so `colab refactor -C repo … .` and `in "core/**"` agree. An absolute path is matched relative to the run's base (`Run::set_base`: MCP sets each tool call's `cwd`), else the working directory, and also as walked, so an absolute glob still matches. A walk of `.` skips hidden directories such as `.claude/`; name such files explicitly.
- **provide examples** for user evaluation
- **update the dsl documentation** docs/dsl.md
- **`colab:ignore` is generic.** `colab_core::ignore::keep_ignored` diffs what a rule did and puts back changes on covered lines, in `Refactoring::apply_at` and `SingleRule`; `find::locate_all` drops covered hits. Backends need nothing for it. A rule's `message` / `severity` live in `Refactoring::notes`; seed reports with `Refactoring::report()` (or `annotate`) so they reach every output.
- **A kept server is a proxy.** By default (`COLAB_KEEP_SERVER=0` turns it off; only the `colab` binary itself defaults on), `Session::start` connects to `colab lsp-daemon` (`colab_lsp_client::daemon`) over a Unix socket instead of spawning the server. The daemon speaks the same protocol, so session code does not change: it caches the first `initialize`, swallows `shutdown` / `exit`, renumbers request ids and document versions per client, closes a client's documents when it goes, and sends `didChangeWatchedFiles` for files changed since. A result from a kept server must equal one from a fresh server (`tests/kept_server.rs`). The socket name includes the colab build, so a new build never reuses an old daemon; a daemon that cannot be reached falls back to a server per command, with a warning, and so does one that closes the connection before it answers `initialize` without saying why (it was stopping, or died: `Session::start` retries once with its own server). `daemon::stop` / `stop_all` return only once each daemon has removed its socket. A client that starts with files changed under the server is not replayed the old `serverStatus` (it would say "quiescent" mid-reload), so it waits out its settle window; and `colab action` lists and resolves again, once, when the server answers "Mismatching assist". A server's stderr is drained and its last lines kept (`Transport::stderr_tail`): a server that exits is reported with what it last said, by the session that started it, or by the daemon as the error of each request it can no longer answer. CLI tests pin `COLAB_KEEP_SERVER=0`, since they check a fresh fake server's start-up.

- **Telemetry records, the binary exports.** `colab_core::telemetry` is a dependency-free span API (`root`, `span`, `client_span`, `annotate`), a no-op until the binary installs `colab-cli/src/telemetry.rs`'s OTLP/HTTP-JSON exporter, which only the standard `OTEL_*` variables configure. A root span ends and is exported per CLI command (`cli::run`), and per MCP tool call (`handle_call`); workers join a trace through `telemetry::current()` / `Context::enter` (the walker does). The exporter also labels traces in habit's terms (`habit.kind` = `command` / `mcp` on the resource, `habit.subcommand` / `habit.flags` on a command's root), which other collectors ignore. Spans carry names, counts, flag names and outcomes only — never paths, contents, rule text or argument values. In async code, open and close a span on one side of an `.await` (the stack is per thread). Tests set `OTEL_SDK_DISABLED=true` so a developer's collector gets nothing.

## Error handling

All fallible code returns `crate::error::Result<T>`. I/O errors must be wrapped with `Error::io_at(path, source)` so the offending path appears in the message; `Error` deliberately has no `From<io::Error>`, so a bare `?` on an I/O result does not compile (the CLI's `io_to_error` is the explicit path-less case: stdout, stdin, child processes, the working directory). Pick the variant by who must act: `Config` when the request should change, `Server` when a language server failed, `Git` when a git command failed or the work tree is in the wrong state (`Error::kind` names them for MCP). The CLI maps any error into a single `error!` log line plus a non-zero exit code; library code never panics on user input. Reserve `expect`/`panic!` for genuinely unreachable conditions (e.g. loading a built-in tree-sitter grammar) and inside `#[cfg(test)]`.

- Idiomatic Rust and idiomatic module conventions.
- Prefer `Result`-returning APIs over `panic!` / `expect` outside tests.
